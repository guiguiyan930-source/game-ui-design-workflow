## 概述

- 项目 ID：`guofeng-card-rpg`
- 产品目标：交付一套可复现的深蓝鎏金国风卡牌 RPG UI 项目（规范 → 页面视觉 → 组件切图 → Atlas/引擎 JSON）
- 成功指标（可验证）：
  1. must-have 六页均有登记视觉稿；主城/编队/背包/战斗已批准
  2. 主城组件包完成无字 PNG、ZIP、Atlas 与三引擎 JSON
  3. `validate_project.py --strict` 通过
- 非目标（明确不做）：服务端经济公式、真实支付、原生引擎工程、自动 OCR 去字

## 用户与场景

| 角色 | 目标 | 关键场景 |
|---|---|---|
| 新玩家 | 认识资源与去向 | 首次进入主城，点抽卡/编队 |
| 回流玩家 | 快速开战或补给 | 主城 → 编队 → 战斗 / 商店 |
| 付费玩家 | 安全完成抽卡与购买 | 抽卡确认、商店购买、货币不足引导 |

## 功能需求

### P0（必须）

| ID | 需求 | 对应页面/系统 | 验收标准 |
|---|---|---|---|
| PRD-01 | 主城展示头像、等级、三类货币与底栏导航 | `home` | 三秒识别主操作；底栏五入口清晰 |
| PRD-02 | 编队可配置前后排并保存 | `formation` | 可见总战力；缺员有 incomplete 态 |
| PRD-03 | 战斗 HUD 展示敌我、血条、灵力与技能 | `battle` | 自动/倍速/退出可达；技能消耗可见 |
| PRD-04 | 抽卡展示卡池、单抽/十连与保底信息 | `gacha` | 消耗货币明确；结果可理解 |
| PRD-05 | 商店分栏商品与购买确认 | `shop` | 价格与货币类型清晰；余额不足可感知 |
| PRD-06 | 背包网格、筛选、详情、使用/出售 | `bag` | 选中详情；使用为主操作 |

### P1（重要）

| ID | 需求 | 对应页面/系统 | 验收标准 |
|---|---|---|---|
| PRD-11 | 主城活动 banner 与邮件红点 | `home` | 有入口但不抢主操作 |
| PRD-12 | 编队推荐阵容 | `formation` | 次操作可达，不遮挡保存 |
| PRD-13 | 战斗记录与波次信息 | `battle` | 不淹没技能栏 |

### P2（可选）

| ID | 需求 | 对应页面/系统 | 验收标准 |
|---|---|---|---|

## 信息架构

- 一级导航：主城、编队、抽卡、背包、商店（战斗由编队/征战入口进入）
- 二级入口：邮件、设置、活动 banner、推荐阵容、一键出售
- 弹层/全屏模态：购买确认、抽卡结果、出售确认（视觉阶段可用页面内嵌表达）

## 文案与本地化

- 默认语言：zh-CN
- 文案原则：短、可读、禁乱码占位；标题可书法感，数字高对比
- 生图策略：页面可用短中文；组件雪碧图默认无文字

## 数据依赖（客户端可见）

| 数据 | 用途页面 | 空态/异常 |
|---|---|---|
| wallet | home, gacha, shop | 余额不足提示与获取入口 |
| player-profile | home | 默认头像/等级占位 |
| roster | formation, battle | 无卡可上阵提示 |
| inventory | bag | 空背包；容量将满 |
| battle-state | battle | 加载中；断线提示 |

## 边界与异常

- 网络失败：主城/战斗显示 offline 或重试入口
- 资源不足：抽卡/商店阻断并导向获取
- 冷却/次数耗尽：抽卡或体力相关提示（文案短）
- 新手引导打断：本迭代不强制引导层，预留不遮挡主操作
